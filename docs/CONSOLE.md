# Trade Console — اپلیکیشن محلی با تب‌های ایجنت

یک رابط وب محلی (بدون هیچ وابستگی اضافه) که روی همان هسته‌ی trade-mcp سوار است.
همان ابزارهایی که OpenCode از راه MCP می‌بیند، در این کنسول هم به‌صورت تب و دکمه
در دسترس‌اند — با این تفاوت که اینجا **ایجنت‌های خودش** را هم داری.

## اجرا

```bash
cd /path/to/trade-mcp
TRADE_MCP_BACKEND=file \
TRADE_MCP_FILES_DIR="/media/.../MetaTrader 5/MQL5/Files" \
.venv/bin/trade-mcp console
```

سپس مرورگر: <http://127.0.0.1:8790>

گزینه‌ها:

```bash
trade-mcp console --host 0.0.0.0 --console-port 8790   # دسترسی از شبکه‌ی محلی
trade-mcp console --no-browser                          # باز نکردن مرورگر
```

MT5 می‌تواند هم‌زمان باز بماند؛ کنسول و OpenCode هر دو به یک لایه‌ی حمل (فایل یا سوکت)
وصل می‌شوند و مزاحم هم نیستند، چون هر فرمان شناسه‌ی یکتا دارد.

## تب‌ها

| تب | چه می‌دهد | از کدام ابزار |
|---|---|---|
| **نمای کلی** | بالانس/اکوییتی/مارجین آزاد، پوزیشن‌های باز، پیشنهادهای در انتظار با دکمه‌ی تأیید | `account_info`, `list_positions`, `list_proposals`, `confirm_proposal` |
| **تحلیل** | تحلیل چند تایم‌فریمی، سوگیری، سطوح کلیدی، سناریوی ورود/حد ضرر/حد سود، هشدارها، نمودار | `analyze_market` |
| **ایجنت‌ها** | ساخت ایجنت با قید، اجرای دستی، چرخه‌ی خودکار | `agents.py` |
| **اخبار** | سرخط‌های RSS (بدون MT5) | `news.py` |
| **ژورنال** | یادداشت‌ها و معاملات ثبت‌شده | `journal_*` |
| **تنظیمات** | پیکربندی فعال + بلوک آماده‌ی اتصال OpenCode | — |

## ایجنت‌ها

هر ایجنت یک قرارداد صریح است:

| فیلد | معنی |
|---|---|
| `name` | نام نمایشی |
| `symbols` | فقط همین نمادها را می‌بیند |
| `max_lot` | سقف حجم هر سفارش (از `TRADE_MCP_MAX_LOT` هم بزرگ‌تر نمی‌شود) |
| `max_risk` | درصد ریسک هر معامله (از `TRADE_MCP_MAX_RISK_PERCENT` هم بزرگ‌تر نمی‌شود) |
| `hours` | پنجره‌ی زمانی مثل `08:00-20:00` (خالی = ۲۴ ساعته) |
| `mode` | `advisory` / `guarded` / `auto` |

### سه حالت اختیار

- **`advisory` (پیشنهاد):** فقط `propose_order` اجرا می‌شود؛ سفارش تا وقتی تو در تب
  «نمای کلی» دکمه‌ی **تأیید** را نزنی ارسال نمی‌شود.
- **`guarded` (خودکار در محدوده):** اگر اطمینان سناریو ≥ ۶۲ باشد و هشدارهای تضاد
  تایم‌فریمی/نوسان انفجاری وجود نداشته باشد، خودش تأیید می‌کند؛ وگرنه پیشنهاد می‌ماند.
- **`auto` (خودکار کامل):** هر پیشنهادی که داخل سقف‌های خودش باشد را تأیید می‌کند.

در هر سه حالت یک قفل نهایی وجود دارد: اگر `TRADE_MCP_ALLOW_TRADING=false` باشد،
`confirm_proposal` هیچ سفارشی نمی‌فرستد و پیشنهاد «در انتظار» می‌ماند. همچنین اگر
حجم محاسبه‌شده از `max_lot` ایجنت بزرگ‌تر شود، پیشنهاد **لغو** می‌شود (نه گرد شدن).

### چرخه‌ی خودکار

در تب ایجنت‌ها فاصله (ثانیه) را بده و «شروع چرخه خودکار» را بزن. هر دور، همه‌ی
ایجنت‌های فعال یک‌بار اجرا می‌شوند. پیش‌فرض خاموش است؛ برای شروع، آگاهانه روشنش کن.

## ایجنت داخلی از کدام مدل استفاده می‌کند؟

کنسول دو موتور تصمیم دارد:

1. **موتور قاعده‌محور** (همیشه فعال): همان `analysis.build_scenario` که ابزار MCP هم
   استفاده می‌کند. هیچ API key لازم نیست.
2. **LLM سازگار با OpenAI** (اختیاری):

```bash
export TRADE_MCP_LLM_BASE_URL="https://api.openai.com/v1"   # یا http://127.0.0.1:11434/v1 برای Ollama
export TRADE_MCP_LLM_MODEL="gpt-4o-mini"                    # یا llama3.1:8b
export TRADE_MCP_LLM_API_KEY="sk-..."
```

مدل فقط JSON برمی‌گرداند (`action`, `confidence`, `stop_loss`, `take_profit`,
`risk_percent`, `reason`). اگر پاسخ مبهم یا نامعتبر باشد، همان موتور قاعده‌محور
تصمیم می‌گیرد. یعنی کنسول بدون کلید هم کار می‌کند و با کلید باهوش‌تر می‌شود.

## API محلی

| مسیر | کار |
|---|---|
| `GET /api/overview` | وضعیت اتصال، حساب، پوزیشن‌ها، پیشنهادها |
| `GET /api/analysis?symbol=XAUUSD&timeframes=M15,H1,H4` | تحلیل خلاصه |
| `GET /api/candles?symbol=XAUUSD&tf=H1&count=120` | کندل خام |
| `GET /api/agents` , `POST /api/agents` | فهرست/ساخت ایجنت |
| `POST /api/agents/<id>` با `{"action":"run"\|"toggle"\|"delete"}` | اجرا/روشن‌خاموش/حذف |
| `POST /api/scheduler` با `{"on":true,"interval":300}` | چرخه خودکار |
| `GET /api/news` | سرخط‌ها |
| `GET/POST /api/journal` | یادداشت |
| `POST /api/proposals/<id>/confirm` | تأیید پیشنهاد |

## همزیستی با OpenCode

- **OpenCode** با `trade-mcp serve` (stdio) وصل می‌شود و ابزارها را به‌صورت
  `trade_*` می‌بیند.
- **کنسول** یک پروسه‌ی مستقل است و به همان پل وصل می‌شود.

اگر هر دو را هم‌زمان روی **سوکت** اجرا کنی، تداخل پورت پیش می‌آید (`8787` فقط یک
شنونده می‌پذیرد). با **پل فایلی** این مشکل وجود ندارد — دو پروسه می‌توانند هم‌زمان
درخواست بفرستند چون هر درخواست شناسه‌ی خودش را دارد.

## عیب‌یابی

| نشانه | کار |
|---|---|
| صفحه باز نمی‌شود | `ss -ltnp | grep 8790`؛ اگر چیزی نیست لاگ کنسول را ببین |
| `address already in use` | کنسول دیگری بالاست: `pkill -f "trade-mcp console"` |
| «MT5 قطع است» | `TradeMCPFile.mq5` روی چارت و Algo Trading روشن باشد |
| ایجنت چیزی نمی‌کند | در تب ایجنت‌ها `mode` و `hours` و `enabled` را چک کن؛ گزارش اجرا دلیل را می‌گوید |
| معامله انجام نمی‌شود | `TRADE_MCP_ALLOW_TRADING=true` و `InpAllowTrading=true` هر دو لازم‌اند |
