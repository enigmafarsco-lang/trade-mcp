# ارزیابی چندمبدأ Kronos در Colab

این نوت‌بوک آماده شده، نه اینکه مدل واقعی در محیط Arena اجرا شده باشد:
`notebooks/kronos_multi_origin_colab.ipynb`

## دادهٔ بیشتر، بدون سفارش و بدون API مدل
روی سیستم MT5 از ریشهٔ پروژه اجرا کنید:

```bash
.venv/bin/python scripts/export_kronos_history.py \
  logs/research-inputs/xauusd_m1_1000.json --symbol XAUUSD --count 1000
```

فایل از قبل موجود را overwrite نمی‌کند. فقط تاریخچه بومی می‌خواند؛ حساب،
ژورنال، قیمت تیک و مسیر سفارش فراخوانی نمی‌شوند. `.env` محلی برای اتصال بار
می‌شود، اما کلیدها چاپ/صادر نمی‌شوند. فایل با دسترسی 600 نوشته می‌شود.
زمان UTC تأییدنشده، تاریخچه تکراری/نامعتبر یا نبود حداقل 420 کندل پیوسته
توقف می‌دهد. آخرین قطعهٔ پیوستهٔ واجد شرایط انتخاب می‌شود؛ شکاف پر نمی‌شود.
آخرهفته/بازار بسته مانع تحقیق تاریخی نیست؛ جعل افست ساعت هم مجاز نیست.
این ابزار روی محیط Arena به بروکر کاربر وصل و اجرا نشده است.

## Colab
نوت‌بوک را در runtime رایگان hosted باز کنید. setup، بررسی PyTorch، دریافت
کد ارزیاب، آپلود فایل بالا، نمایش طرح ثابت، سپس سلول مدل و دانلود را به‌ترتیب
اجرا کنید. وابستگی/وزن فقط در Colab نصب می‌شود. Google login را شخصاً انجام دهید.

طرح پیش‌فرض: 5 مبدأ، حداقل فاصله 60 دقیقه، context حداقل120 کندل و holdout60؛
حداقل ورودی420 کندل. final_test آخرین مبدأ است و جدا گزارش می‌شود؛ این فقط
یک مبدأ تست نهایی است، نه شواهد کافی تعمیم یا سودآوری. مقایسهٔ هر افق 15/30/60
با قیمت ثابت و روند خطی15 کندل انجام می‌شود. seed42 ثبت می‌شود اما GPU و
checkpointهایی با نام غیرimmutable تضمین بازتولید بیت‌به‌بیت ندارند.

نوت‌بوک همان ارزیاب تست‌شدهٔ commit ثابت
`4f66fe8b4ea4a3ba8f68ca2d96f70d1d05b426da` را دریافت می‌کند؛ فرمول‌ها دوباره
در نوت‌بوک کپی نشده‌اند. پنج inference و بدون retry/انتخاب نمونه برنده انجام
می‌شود. خروجی خوب و بد هر دو در `kronos_multi_origin_research.json` صادر می‌شوند.
فایل گزارش، artifact کندل زنده نیست؛ به `KRONOS_FORECAST_PATH` وصل نشود.

این تغییر سفارش جدید، فعال‌سازی بودجه، تغییر آستانه، خرید سرویس یا اجرای واقعی
مدل را انجام نمی‌دهد. برای اتصال مرورگر/Google و تخصیص منابع Colab ممکن است
مداخلهٔ کاربر لازم باشد. raw ورودی/خروجی را وارد Git نکنید؛ فقط گزارش پاک‌شده.

## تشخیص امن شکست صادرکننده
نسخهٔ اصلاح‌شده به‌جای خطای کلی، کد ثابت چاپ می‌کند:
- `HISTORY_REQUEST_FAILED`: درخواست تاریخچه از MCP شکست خورد؛ اتصال محلی بررسی شود.
- `UTC_UNVERIFIED`: ساعت بروکر قابل تأیید نبوده؛ timezone رایانه جایگزین نشود.
- `EMPTY_HISTORY` / `NO_CLOSED_ROWS`: دادهٔ قابل استفاده دریافت نشده است.
- `INSUFFICIENT_CONTIGUOUS_HISTORY`: تعداد ردیف دریافتی، بسته و طول بلندترین قطعه
  نمایش داده می‌شود. اگر تاریخچه کم است می‌توان با مسیر جدید و count حداکثر5000
  یک درخواست دستی دیگر داد؛ هیچ retry خودکار یا gap filling وجود ندارد.
- `INVALID_TIMESTAMP` / `INVALID_ROW` / `INVALID_OHLCV`: دادهٔ نامعتبر؛ حذف کنترل مجاز نیست.
این تشخیص فقط کد و شمارنده است؛ متن خام خطای transport چاپ نمی‌شود.

## تحقیق در تعطیلی بازار بدون ادعای UTC
وقتی ساعت سرور قابل تأیید نیست، حالت صریح زیر به تیک زنده وابسته نیست:

```bash
.venv/bin/python scripts/export_kronos_history.py \
  logs/research-inputs/xauusd_m1_broker_research.json \
  --symbol XAUUSD --count 1000 --broker-time-research
```

این حالت **تبدیل به UTC نیست**: برچسب ساعت بروکر را بدون تغییر نگه می‌دارد،
جدیدترین کندل را حذف می‌کند (برای هر کندل باقی‌مانده، کندل بعدی دیده شده)،
و فقط قطعهٔ پیوستهٔ حداقل420کندلی را صادر می‌کند. شمارش/قیمت/حجم همچنان
اعتبارسنجی می‌شوند. ورودی تکراری رد می‌شود، داده ساختگی تولید نمی‌شود.
فایل با `timezone=broker_wall_clock` و `utc_verified=false` مشخص می‌شود.
حالت پیش‌فرض UTC و کد bridge/live loader هیچ تغییری نکرده‌اند.

نسخهٔ جدید نوت‌بوک این فایل را فقط به‌عنوان تحقیق می‌پذیرد و مبنای زمان را
در گزارش ثبت می‌کند. تاریخ‌ها در این حالت «برچسب بروکر» هستند، نه لحظهٔ UTC؛
حتی اگر نام داخلی `origin_time` یا `forecast_origin` باشد. ویژگی‌های تقویمی
Kronos با همین ساعت بروکر محاسبه می‌شوند و نتایج با آزمایش UTC یکی نیستند.
این روش اثبات منطقهٔ زمانی بروکر، رفع DST یا تأیید تازگی زنده نیست.
برای خروجی UTC همچنان به زمان/منطقهٔ زمانی تأییدشده نیاز داریم.
